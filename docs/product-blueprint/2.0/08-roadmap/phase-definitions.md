# Phase Definitions

Every phase entry/exit is evidence-based. Entry: predecessor exit and owner decisions available. Exit: artifacts reviewed, tests/analysis complete for scope, high risks assigned, no unresolved contradiction silently carried. Phase-specific examples:

- Discovery: unknowns recorded, not converted into facts; user research source retained.
- Definition: product charter and non-goals approved with owner/date.
- Requirements/UX: one authoritative register, role/permission/journey and a11y matrix.
- Architecture/data: approved ADRs, migration and threat model, failure matrix.
- Infrastructure: named environment, IAM/secrets/signing/observability and rollback validated.
- Implementation: the product team may plan implementation, but this documentation assignment never authorizes it.
- Quality/release: exact commit, device/live/store/backend evidence and post-deploy runbook.
