# Implementation Readiness

## Ready for implementation planning

Android-first product scope, local-first data boundary, entitlement-first AI policy, and the inclusion of Birthday Autopilot with explicit recipient opt-in and exact-message approval are approved for implementation planning. This is not authorization to deploy, enable production SMS, publish a store release, or change retention/account policy.

## Not ready

Destructive Person/Birthday schema migration; per-cycle history conversion; backup retention/restore/deletion; account switching/local ownership; paid AI packaging; public Hosting identity; automatic-SMS activation; auto-prepare; non-Android clients/locales; numerical SLO/capacity; production deployment. Each is blocked by data inventory, policy/device evidence, or explicit stakeholder approval. Automatic SMS is in scope, but both Dart/native gates remain disabled until these release gates pass.

Preserve legacy behavior until migration/rollback evidence is accepted. Product-scope approval does not imply consent to use personal data, deployment credentials, commit/push, store submission, or production sending.
