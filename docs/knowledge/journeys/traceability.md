## Separate server capability, not a Flutter user journey

The sender control plane has registration, lease, claim, arm, outcome, retry, transfer, reset, release and scheduled sweep operations. Those APIs are mapped in the [API/backend inventory](../api-backend-map.md), but no mobile client call path was found for sender registration/claim/arm. They must not be inserted into J-04 as if app-connected. The current mobile SMS gate defaults false and the Play manifest excludes `SEND_SMS`.

## Trace quality limits

- Seven journey IDs are documented; substeps and failure branches are included above. This count excludes individual route transitions and OS callbacks as separate journeys.
- API and database edges indicate source call paths. Cloud Functions/Hosting deployment and Firestore production rules are not established.
- A test file location means coverage exists in a test suite; it is not proof every table row has a matching assertion or that the suite passed in this session.
