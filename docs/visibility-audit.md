# Visibility, Conditional UI & Scenario Intelligence Audit

Scope: every screen, section, card, button, field, menu, action, status indicator, and CTA
across AI-Birthday. Rule set, scenario analysis, decision table, screen-by-screen inventory,
and the implementation log.

Status of each finding: **✅ already correct**, **🔧 fixed in this audit commit**, **📝 documented
only (needs a product decision or a later device phase)**.

---

## 1. Visibility rule set

| Rule | Meaning | Where it bites |
| --- | --- | --- |
| VISIBLE | User can see and use it now | default for valid actions |
| HIDDEN | Irrelevant to current state; must not appear | Dead "Message Studio" on birthday-less contacts |
| DISABLED | Relevant but not usable right now | Generate button while drafting |
| CONDITIONAL | Visible only when a condition holds | Action Needed section, tone controls, reminder leads |
| LOCKED | Visible but requires entitlement/setup | AI writing for free tier; cloud backup without sign-in |
| LOADING | Temporary UI while data resolves | splash spinners |
| EMPTY | Feature exists, no data yet | People / History / Calendar / Dashboard empty states |
| ERROR | Normal UI replaced or augmented by recovery | AI generation failure banner |
| SUCCESS | UI changes after completion | Sent → Confirm Sent → Completed |
| DEPRECATED | Should be removed | none found in this pass |

Discipline applied: **hidden beats disabled when the action can never work; visible-with-recovery
beats hidden when the user must understand setup exists** (AI, notifications, phone number).

## 2. Scenario analysis (A–Y)

### Scenario A — First-time user (no people / birthdays / AI / history)
- Onboarding gate covers first run (5-step loop + Skip). ✅
- Dashboard empty state: headline "Let's add your first birthday", subtitle explaining the
  product, primary **Add Birthday** + **Import Contacts**. ✅
- No AI configuration UI on Dashboard for a fresh user — the AI-area lives in Settings and
  Message Studio, both reachable when the user actually tries to draft. ✅
- Bottom-nav stays at 5 destinations: Dashboard, People, Calendar, History, Settings all render
  meaningful empty states (Calendar gets one in this commit 🔧). Navigation is not removed for
  first-run users, since every tab has a real purpose and a real empty state (📝 decision: keep
  all 5 tabs; removing tabs for first-run adds navigation churn with no information gain).

### Scenario B — People exist, no upcoming birthdays
- Upcoming Section renders an empty Card reading "No upcoming birthdays tracked in the next 30
  days." ✅ (not a bare skeleton — the reason is stated).
- Quick Actions (Add/View People/Settings) remain below, giving a next step. ✅
- 📝 Enhancement considered and deferred to the Dashboard redesign phase: when there are people
  but zero upcoming, the empty card could add a "Add a birthday" CTA. Low urgency — the section
  already states its meaning and Quick Actions sit directly beneath.

### Scenario C — Birthday is today
- Today's Birthdays section becomes the top card group, accent-marked, person → date → status
  chip → one contextual action. ✅
- Priority order is already Person → Message action → context (Channel + phone hint); settings
  and history are not promoted on this screen. ✅
- 🔧 Fixed: Message Studio on a completed birthday no longer leads with "Send on WhatsApp" —
  it leads with **View in History** (see Scenario Q).

### Scenario D — Birthday tomorrow / 1–2 days out
- Upcoming (≤30 days) cards show "Birthday in N days" with the message-preparation path via the
  Action Needed section when status is `reminderDue`/`messageNotPrepared`/`messageDrafted`/
  `failed` — these render "Draft Greeting" / "Review Draft" CTAs. ✅
- No false urgency: nothing beyond a countdown chip changes at 3–6 or 7+ days; the "Send" CTA
  only surfaces at `messageReviewed`/`readyForDelivery`. ✅
- Notification leads (7/2/1-day + today reminders) are generated by the reminder scheduler and
  previewed in Settings only when reminders are enabled. ✅

### Scenario E — Distance-based urgency ladder
| Days out | Behavior | Status |
| --- | --- | --- |
| 7+ | Countdown chip only; no send CTA | ✅ correct |
| 3–6 | Countdown chip only; Action Needed only if a status forces it | ✅ correct |
| 1–2 | Same; reminderDue birthdays enter Action Needed with "Draft Greeting" | ✅ correct |
| today | Today's Birthdays section, accent emphasis, Send-ready CTAs | ✅ correct |
| passed | Rolls off upcoming list; the next cycle's card reappears via BirthdayEngine | ✅ correct |

### Scenario F — Birthday has passed
- The passed birthday leaves the upcoming window automatically (engine computes next cycle). ✅
- Nothing is shown as "missed"; the app always points at the upcoming cycle. 📝 Product choice
  confirmed: no missed-birthday recovery UI (users came to the app to *not* miss; one year's
  skip silently rolls into the next). Do not add.
- Message Studio for the passed birthday remains reachable via People/Calendar/History, so the
  user can still draft or resend. ✅

### Scenario G — AI fully available (Pro + key or Nano)
- Only the generation controls matter: Tone/Length/custom instruction chips, Shorten/Expand/
  Translate/Variations, Generate. All render. ✅

### Scenario H — No Gemini API key (and no Nano)
- 🔧 Fixed: the studio now pre-warns instead of failing after the tap. `Generate with AI`
  becomes **Unlock with Pro** when entitlement is absent (the router gates on entitlement
  first), and tone/length/Variations controls are hidden with a one-line explainer. Manual
  writing and every delivery action remain fully available.
- Settings keeps the full "Get Gemini API key ↗ / How to connect" setup path and the key field. ✅

### Scenario I — Key exists but invalid / quota / network / provider failure
- Settings "Test Connection" distinguishes **Connected / Invalid Key / Quota Exceeded /
  Network Unavailable / Error** with per-state banners. ✅
- Studio generation failures surface AppFailure (message + detail + action) in the error banner
  with **Retry / Write manually / AI Settings**. ✅
- 📝 Documented gap: the studio banner composes failures into one string; the Settings-style
  per-state treatment (invalid key → "fix key in Settings", quota → "wait or upgrade limits")
  is deferred to the Message Studio redesign phase, where the banner becomes a typed state.

### Scenario J — On-device AI (Nano) available
- Settings "On-Device Intelligence" card states "Ready on device for offline generation" with
  an AVAILABLE badge. ✅ No raw internals (no AICore plumbing text). ✅

### Scenario K — On-device AI unavailable
- Settings states "Not available on this device hardware" with NOT AVAILABLE badge, and the
  storage note explains key-based Gemini as the alternative. ✅ Nothing is presented as usable
  when it is not. ✅

### Scenario L — Person has no phone number
- 🔧 Fixed: instead of a dead-end snackbar on tap, the studio's primary action becomes
  **Add Phone Number** (jumps to the contact editor); SMS is hidden (cannot SMS without a
  number); **Share Sheet** and **Copy Text** remain as fully working alternatives.
- Dashboard action cards already paint "No phone number" as a hint. ✅

### Scenario M — Invalid phone number
- 🔧 Fixed: a non-empty but unusable number yields **Fix Phone Number** as primary plus an
  inline correction note ("needs a country code, e.g. +1 555 123 4567"). WhatsApp/SMS are not
  presented as if they will work. Share/Copy remain.

### Scenario N — WhatsApp not installed / launch fails
- Launch failure is caught; the handoff dialog explains "could not be opened automatically",
  offers the message in a selectable box, and shows **Did you send the message? Not Sent Yet /
  Yes, Message Sent!**. Birthdays transitions to `failed`. ✅
- 📝 Documented: a "was the app installed?" pre-check (`canLaunchUrl`) is possible but the
  current failure path already recovers honestly; defer to the delivery redesign phase.

### Scenario O — WhatsApp opens successfully
- The app does **not** assume sent: dialog asks **Did you send the message?** with explicit
  **Not Sent Yet** / **Yes, Message Sent!**. Birthdays state = `handedOff`. ✅

### Scenario P — Opened but not sent
- `handedOff` ≠ sent: Dashboard action becomes **Confirm Sent**, history shows **Opened in
  WhatsApp**, not "Sent". ✅

### Scenario Q — User confirms sent
- Only "Yes, Message Sent!" flips state: birthday `completed`, draft `confirmedSent`, history
  status **Sent**, snackbar "Celebration confirmed as sent! 🎉". ✅
- 🔧 Fixed post-completion UI: Dashboard already excludes completed birthdays from Action
  Needed (badge carries "Completed"); the studio now leads with **View in History** instead of
  a stale "Send on WhatsApp" CTA. Resend remains available via the alternate channels (the
  History → Studio path makes resending an intentional feature).

### Scenario R — Notification permission denied (first enable)
- Switch tap → `requestPermission()` → denied → snackbar + switch reverts to off. ✅

### Scenario S — Permission granted
- Reminder leads (7/2/1 day + Today), Quiet hours, test notification all appear only while
  enabled. ✅ Nothing nags a granted user. ✅

### Scenario T — Notifications revoked at OS level after being enabled
- 🔧 Fixed: Settings now detects the revoked state — when reminders are enabled but
  `hasPermission()` reports blocked, a warning card ("Notifications are blocked in system
  settings…") with **Re-enable notifications** appears. Recovery re-requests permission and
  reschedules the reminder plan.

### Scenario U — Quiet hours active
- Quiet hours row shows "No delivery between X and Y"; reminder planners honor the window. ✅
  Controls stay visible with adjusted-timing language baked into the row. ✅

### Scenario V — Multiple birthdays on the same day
- Calendar groups them on one day (dots ≤3 + tap-for-list bottom sheet); the sheet lists each
  person with turns-age and a studio link. ✅ No clutter: dots collapse, list opens on demand.
- Dashboard lists each birthday in its own card (no cross-merging) — acceptable for a card
  layout; the calendar remains the grouped view. 📝 Noted.

### Scenario W — No history
- History renders a real empty state: "No activity yet — Prepared and sent messages will
  appear here." ✅ No empty table structure. ✅

### Scenario X — History has many entries
- In-place terse cards with per-status chips; no pagination. 📝 Documented, deferred to the
  History redesign phase: add month grouping + scrolling density; search/filter only if counts
  grow (unlikely for a 1-per-birthday message log).

### Scenario Y — Many people
- People uses a flat ListView with popup actions per person — serviceable to dozens, but no
  search/grouping. 📝 Deferred: add alphabetical section headers + search in the People redesign
  phase. At 0 people the empty state with Add + Import leads. ✅

## 17. Screen-by-screen inventory (concise)

### Dashboard
**Purpose:** command center: What / Who / Why / Next. **Default:** header + upcoming + quick
actions. **Required data:** people + birthdays streams. **Visible:** header, Action Needed
(conditional), Today's (conditional), Upcoming, Quick Actions. **Hidden:** nothing state-wise.
**Disabled:** nothing (buttons always valid). **Conditional:** Action Needed, Today's, empty-state
CTAs, phone hint. **Empty:** hero + "No upcoming" card. **Loading:** full spinner. **Error:**
"data safe" copy. **Success:** status badges/CTAs cascade. **Primary CTA:** status-driven, else
Add Birthday. **Secondary:** Quick Actions. **Destructive:** none. **Navigation:** shell tab.
**Permissions:** none. **AI:** none on-screen. **Subscription:** none. **External:** none.
**A11y:** 48dp targets, semantics on chips/cards (Phase 1–3). **Changes:** none needed — completed
already excluded from Action Needed (verified).

### People & Contacts
**Purpose:** recipient CRUD + import. **Default:** sorted list. **Required data:** people.
**Visible:** list, per-person menu (Studio/Edit/Delete), bottom sheet, FAB, import/export ⠇.
**Conditional:** Menu "Message Studio" (hasBirthday — 🔧), sheet "Draft Message with AI"
(hasBirthday — 🔧), facts rows, countdown chips. **Empty:** Add + Import. **Loading:** spinner.
**Error:** recovery copy. **Success:** delete + Undo toast; import count toast. **Primary:** Add.
**Destructive:** Delete (dialog + Undo). **Permissions:** contacts (privacy dialog first).
**A11y:** large tiles, tooltips. **Changes:** hide dead actions for birthday-less contacts.

### Calendar
**Purpose:** annual view. **Default:** current month grid. **Required data:** people.
**Visible:** month nav, weekday header, dots, day bottom sheet. **Empty:** 🔧 added.
**Conditional:** day tap list, today ring. **Permissions/AI/Sub:** none. **A11y:** semantics
per day ("Day N, M birthdays", button). **Changes:** empty state + Add CTA.

### History & Activity
**Purpose:** message/delivery timeline. **Default:** terse cards. **Required data:** drafts +
people. **Visible:** status chips (Sent/Opened/Ready/Reviewed/Draft), body, Copy, Studio.
**Empty:** "No activity yet". **Success:** Sent vs Opened distinction. **A11y:** high-contrast
chips. **Changes:** none needed now; grouping deferred to redesign (Scenario X).

### Message Studio
**Purpose:** draft, generate, deliver. **Default:** recipient + controls + editor + actions.
**Required data:** birthday + person (+ entitlement). **Visible:** recipient card, AI controls
(Pro only 🔧), editor, delivery actions, error banner (on failure). **Conditional:** SMS
(usable phone 🔧), primary swaps (completed → View in History 🔧; no phone → Add Phone 🔧;
invalid phone → Fix Phone 🔧; locked → Unlock with Pro 🔧), AI chips (Pro 🔧).
**Empty/Error/Success:** banner trio retained; generation never erases context. **External:**
WhatsApp/SMS/Share handoffs (never claim sent). **A11y:** semantic buttons, snackbars.
**Changes:** 5 conditional-CTA fixes + AI pre-warn.

### Settings
**Purpose:** account, backup, subscription, AI, reminders, help. **Default:** full section list.
**Required data:** auth, entitlement, reminder settings, Nano + key state. **Conditional:**
reminder leads (enabled), upgrade (not Pro), key status badges, revoked-permission warning (🔧),
exact-alarm Fix. **Permissions:** notifications, exact alarm. **AI:** key test states + Nano
badge + setup guide. **Subscription:** free/pro + restore. **Privacy:** backup + key notes.
**Changes:** Scenario T warning + recovery.
