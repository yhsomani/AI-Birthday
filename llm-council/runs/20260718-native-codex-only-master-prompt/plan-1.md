# Plan

## Overview

Build one repository-specific prompt around a product-intake ledger, current primary-source research, an independent Codex-only council, a locked decision package, atomic implementation tasks, and journey-level verification. Treat user experience and truthful Android/iOS promises as first-class contracts.

## Scope

- Read PROJECT_ABOUT.md first and preserve its source-of-truth precedence.
- Record that no AGENT.md or AGENTS.md exists; load them if added later but never invent absent authority.
- Map business outcomes, user jobs, current behavior, desired behavior, platform edition, states, data/privacy, accessibility, performance, release implications, confidence, evidence, owner, and reopen condition.
- Ask one compact optional intake round. Infer repository facts and ask only material product, privacy, distribution, external-system, or irreversible choices.
- Use three independent gpt-5.6-sol planners and an anonymized gpt-5.6-sol judge; no other development-agent provider.
- Audit every principal journey and every relevant loading, empty, stale, partial, offline, error, cancellation, retry, process-death, and recovery state.
- Finalize decisions before edits, then implement dependency-ordered vertical tasks one at a time.

## Priority Evidence Leads

- Unsaved message and policy edits can disappear on navigation.
- Permission-repair results lose denied, permanently-denied, and unavailable distinctions.
- High-consequence reviews do not consistently move accessibility focus.
- Home may not satisfy the Today plus next-seven-days contract.
- Latest Android test projection errors are not rendered.
- Activity privacy minimization may prevent users from identifying the affected person and needs an explicit product decision.
- Activity detail scans many pages instead of using a direct projection.
- Repair routes are coarse, bulk enrollment counts may mislead, time entry is error-prone, and viewport adaptation is not proven.
- Privacy actions are cognitively dense for older and less technical users.

## Implementation Contract

Each task owns one observable behavior, exact files, dependencies, risk, acceptance criteria, targeted tests, broader regression gates, rollback, and evidence. Preserve unrelated dirty-tree changes. Parallelize read-only work and only disjoint writes with explicit ownership.

## UX and Accessibility Validation

For each changed journey verify Back and unsaved-edit behavior, deep-link restoration, Android/iOS promise copy, TalkBack/VoiceOver labels/roles/states/hints/focus/live announcements, 200 percent text, compact and large viewports, dark/high contrast, reduced motion, English/Hindi, pseudo-RTL/bidi, 48-point targets, non-color status, privacy disclosures, and real-device evidence proportional to risk.

## Completion

Every accepted ledger row needs code/test/artifact evidence or an explicit external blocker. A build, simulator smoke, successful test SMS, or opened MessageUI composer is never release authorization. Update only directly affected authoritative or operational documentation.
